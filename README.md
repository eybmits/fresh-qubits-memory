# The Memory Limits of Noisy Quantum Reservoirs

Scientific project for **“The Memory Limits of Noisy Quantum Reservoirs”** by Markus Baumann, Jonas Stein, and Claudia Linnhoff-Popien (LMU Munich).

The manuscript studies how the number of freshly prepared input qubits per cycle limits the memory of a noisy quantum reservoir. This repository preserves the supplied manuscript versions, provides editable LaTeX sources and figures, records a research and validation plan, and includes an independent numerical reproduction of the majority-refresh example.

**Current manuscript (16 October 2026):** [PDF](paper/memory_limits_2026-10-16.pdf) · [LaTeX source](paper/source/memory_limits.tex) · [build instructions and version history](paper/README.md). This version imports the newly supplied manuscript and uses the requested abstract, restores the supplied title, and updates the author list. The earlier 15 October PDF remains unchanged. The supplied manuscripts are the source of the theoretical claims; the numerical checks do not verify their proofs. Publication and peer-review status are not established by the supplied material.

## Scientific scope

Each cycle overwrites a register of at most $k$ qubits, applies a fixed unitary, and independently depolarizes every qubit with fixed $0<q<1$. For the driven state after the initial transient, the current manuscript defines memory depth using trace distance between states generated by histories with a common recent-input window. It claims a worst-case memory depth of $\exp[\Theta_q(k)]$ at fixed accuracy, independent of the total register size $n$ (Theorem 1).

The matching construction uses an odd number $r$ of repetition copies, $k=r+2$ fresh qubits, and $n=2r+2$ total qubits. With $p=(1-q)/2$:

$$
p_r=\sum_{j=(r+1)/2}^{r}\binom{r}{j}p^j(1-p)^{r-j},\qquad
\lambda_r=1-2p_r,\qquad f_b(t)=(-1)^b q\lambda_r^t.
$$

Table I of the original 15 October manuscript reports the largest integer $T_r$ with $\lambda_r^{T_r}\geq 1/2$; the same lifetimes appear in Figure 4 of the current manuscript. At $q=0.9$, $r=15$ ($k=17$) gives **1,894,286 hold cycles**. These are ideal-unitary/noise cycles, not elementary gate cycles.

The exponential upper and lower bounds match in order, not in constants. A long memory does not establish classical computational hardness: the example above has a one-scalar recurrence. The current manuscript focuses on memory limits and does not contain the earlier classical-learning theorem. See the [current version note](docs/manuscript-2026-10-16.md); the [original paper summary](docs/paper-summary.md) remains explicitly tied to the 15 October baseline.

## Quick start

Python 3.11 or newer is required. The calculation and tests use only the Python standard library.

```bash
git clone https://github.com/eybmits/fresh-qubits-memory.git
cd fresh-qubits-memory
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m unittest discover -s tests -v
python scripts/reproduce_table1.py --output-dir results/table1
```

The script writes CSV values and JSON metadata. The committed [baseline output](results/table1/) is generated from the equations, with the lifetime and conservative-guarantee rows checked against Table I. No stochastic sampling is used. Package installation uses setuptools as its build tool; runtime calculations need no third-party packages.

Optional flags are `--q`, `--copies`, and `--precision`; see `--help`. The implementation accepts odd `r` from 1 to 255 and finite-decimal `q` in `(0,1)` with at most 100 decimal places. Output precision is 30–512 digits; adaptive working precision is capped at 4096 digits and extreme cases that exceed the bound are rejected. See the [validation record](docs/validation.md) for the tested scope and the manuscript's display-rounding convention.
